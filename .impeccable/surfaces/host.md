# Host operations surface brief

Mode: Operate. Scope: `/host` after a room exists.

The trusted event host must read room state, match time, attendance, score order,
and all thirty marker states at a glance while controlling only valid state
transitions. The route runs for the duration of a live event, often on a laptop
beside other operational work, so density, stable placement, and explicit text
matter more than spectacle.

## Direction contract

**THESIS:** The host sees one field ledger for the whole hunt, not a collection
of equal dashboard cards. Refuse a metric-tile grid and keep the room transition
as the sole hot action.

**OWN-WORLD:** The incumbent Night-Hunt Field Pass remains intact: ink-violet
ground, bone type, thin lavender rules, cyan live state, orange action, compact
monospace telemetry, curved operational sheets, and square marker cells.

**STORY:** Share the room code, verify connected hunters, start once, then monitor
score order and marker pressure until the authoritative deadline unlocks final
publication. Every state name and marker color also has written meaning.

**FIRST VIEWPORT:** On desktop, room control occupies the narrower left column;
the live ledger fills the wider right column with roster first, leaderboard next,
and a dense thirty-cell marker strip. Mobile stacks the same order without hiding
controls or status behind horizontal scrolling.

**FORM:** Code-led Operate extension, first among the existing host information
structures. `seed: none (unavailable)`. The signature interaction is the marker
strip and leaderboard updating in place while the room transition control stays
anchored in the left ledger.

**FINISH:** unreviewed and undocumented is unfinished; this build ends with the
finish review, the verdict, DESIGN.md, and every shipping raster carrying its
provenance
